Part 1

What Is MCP?

Model Context Protocol is an open standard (by Anthropic, 2024) that lets AI models call external tools and read external data through a unified client-server interface.

💡

Key idea

MCP standardizes how an AI client discovers and invokes tools. Instead of writing a bespoke integration per API, you write one MCP server and any compatible client can use it.

🔧 Tools

Functions the server exposes - e.g. get_weather(city), query_db(sql). The AI model can decide to call them.

📄 Resources

Read-only data the server provides - e.g. a config file, a database schema. Clients can list and read them.

💬 Prompts

Reusable prompt templates the server offers - e.g. "generate a code review for this diff".

🔄 Transport

Communication layer: stdio (subprocess) for local tools, or HTTP + SSE for remote servers.

Part 2

How Freebuff Works

Freebuff is a coding agent with a fixed, built-in toolset. It reads code, edits files, runs commands, searches the web, and previews web apps.

Part 3

The Gap: Why MCP Does Not Work in Freebuff

Freebuff tools are compiled into the platform. There is no plugin interface, no tool registry, and no transport layer to connect external MCP servers.

What Freebuff Lacks

No MCP client library
No tool registration API
No stdio/SSE transport
No MCP server config

What Freebuff Has

Curated, high-quality built-in tools
Direct filesystem + terminal access
Web search + browser preview
Todo/plan management

Could SiteVerdict become an MCP server?

Absolutely. You could wrap the FastAPI endpoints with the Python mcp SDK so that any MCP-compatible client (Claude Desktop, Cursor, etc.) could call analyze_site or demo_portfolio as tools. This would be straightforward given the existing API surface - but it is a change to SiteVerdict, not to Freebuff.

Part 7

Workarounds Available Today

Even without native MCP support, you can achieve similar goals using Freebuff's existing tools.

Use the Terminal Tool to Call External APIs

Since Freebuff has shell access, you can curl or python any HTTP endpoint - effectively doing what an MCP HTTP transport would do, just manually.

# Example: querying an external service via terminal curl -s https://api.example.com/v1/data -H "Authorization: Bearer $TOKEN" | jq . # Or run a Python script that calls the API python -c "import requests; r = requests.get('https://...'); print(r.json())"

Run MCP Servers as Subprocesses

You can start an MCP server process and communicate with it via its stdio transport, though this requires manual JSON-RPC formatting.

# Start an MCP server (if installed) echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | npx -y @modelcontextprotocol/server-filesystem /path # This works but is not integrated - you would need to # parse and relay the output yourself.

Build It Into Your Project

The best path: add MCP server support to your own project (like SiteVerdict), then use Freebuff to build and debug it.

# Install the Python MCP SDK in your project pip install mcp # Write an MCP server wrapping your FastAPI endpoints # Freebuff can help you build and test this!

Bottom Line

No - Freebuff does not support connecting external MCP servers today.

Freebuff is a self-contained coding agent with a fixed, high-quality toolset. It cannot load or invoke MCP servers. However, you can use Freebuff's shell access to run MCP servers manually, or build MCP server support into your own projects with Freebuff's help.
